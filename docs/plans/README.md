# Execution plans

Use a plan for work that spans multiple changes, has important design choices,
or leaves follow-up debt. Small, self-contained fixes do not need one.

## Lifecycle

1. Create `active/<topic>.md` from the outline below.
2. Keep status, validation evidence, and material decisions current as work
   proceeds.
3. Move it to `completed/` when shipped; retain it as repository-local context.

## Outline

```md
# <Topic>

## Goal

## Scope and non-goals

## Steps
- [ ] ...

## Decisions

## Validation

## Follow-up debt
```
